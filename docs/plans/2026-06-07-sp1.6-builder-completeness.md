# SP1.6 — Builder completeness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans, task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the four tracked builder gaps so every reference manifest in `catalog/` is actually buildable: custom Docker images (Jinja2 override), `extra_binaries`/`extra_sources` packaging (SP1.4b), the dashboard producer (spec §7.2), and an L3 install smoke-test that proves RPM/DEB packages install and the service answers.

**Architecture:** A shared foundation threads the manifest's source directory into the build (`BuildContext.manifest_dir`) and stages `assets/` + downloaded `extra_sources` into each package/Docker work dir so `extra_files.source` and Dockerfile `COPY` resolve. On top of that: (A) `DockerTarget.dockerfile` opt-in renders a Jinja2 template through a new `forge.packaging.template` seam — the extension point for any future exotic Dockerfile, no core change; (B) the exporter producer fetches extra binaries (same release archive) and extra sources (URLs) and feeds them to nfpm + Docker; (C) a `DashboardProducer` resolves `spec.source` (grafana/url/git/local), validates the JSON, emits a `grafana-dashboard` Artifact; (D) a gated, out-of-`make ci` L3 test installs the produced RPM/DEB in the target-distro container and curls the exporter port.

**Tech Stack:** Python 3.12, Pydantic v2, Click, httpx, **jinja2 (new runtime dep)**, nfpm, docker; pytest with injected fakes (no network in `make ci`); L3 gated by `FORGE_NETWORK_TESTS`/`FORGE_DOCKER_TESTS`.

```python
"""Stage a manifest's committed ``assets/`` into a build work dir.

``extra_files.source`` entries are written as ``assets/<file>`` (resolved by
nfpm relative to its cwd = the work dir) and custom Dockerfiles ``COPY`` files
from the build context root. Staging the tree once makes both resolve without
the producer knowing which files a given manifest references.
"""

from __future__ import annotations

import shutil
from pathlib import Path


def stage_assets(manifest_dir: Path | None, work_dir: Path) -> None:
    if manifest_dir is None:
        return
    assets = manifest_dir / "assets"
    if not assets.is_dir():
        return
    shutil.copytree(assets, work_dir / "assets", dirs_exist_ok=True)
```

```python
"""Jinja2 template seam for custom Dockerfiles (spec §7.1 extension point).

A manifest may opt into a fully custom Docker image via
``artifacts.docker.dockerfile``; this renders that template with the manifest
as context. ``StrictUndefined`` makes a typo in a template fail loudly instead
of silently rendering an empty token. Templates are repo-controlled (not network
input), so no autoescape (Dockerfiles are not HTML) and no sandbox needed.
"""

from __future__ import annotations

from pathlib import Path
from typing import Any

from jinja2 import Environment, StrictUndefined, TemplateError
from jinja2.exceptions import UndefinedError

from forge.domain.errors import BuildError


def render_template(template_path: Path, context: dict[str, Any]) -> str:
    if not template_path.is_file():
        raise BuildError(f"custom Dockerfile template not found: {template_path}")
    try:
        source = template_path.read_text(encoding="utf-8")
        env = Environment(undefined=StrictUndefined, autoescape=False)  # noqa: S701 — Dockerfile, not HTML
        return env.from_string(source).render(**context)
    except UndefinedError as exc:
        raise BuildError(f"undefined variable in {template_path.name}: {exc}") from exc
    except TemplateError as exc:
        raise BuildError(f"failed to render {template_path.name}: {exc}") from exc
```
