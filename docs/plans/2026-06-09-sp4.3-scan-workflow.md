# SP4.3 — Scan workflow (auto-bump PRs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 6-hourly cron detects outdated exporters and opens one signed,
auto-merging bump PR per item; each bump PR's CI builds the changed item
**unsigned** (shift-left), so a broken upstream release turns the PR red and never
merges.

**Architecture:** One engine change — `DetectedVersion` gains `latest_raw` (the
verbatim upstream tag) so `mh watch --json` can feed `mh bump --to <raw-tag>` and
preserve the manifest's `v`-prefix download-URL convention (SP4.2 bump is
verbatim). Then two GitHub Actions workflows: `scan-updates.yml` (cron → detect →
fan-out matrix → per-item bump + signed PR + auto-merge) and `forge-bump-ci.yml`
(PR validation building the changed item unsigned, no secrets).

**Tech Stack:** Python 3.12 (frozen dataclass, Click `CliRunner`), pytest,
`mypy --strict`, ruff; GitHub Actions (`actions/create-github-app-token`,
`peter-evans/create-pull-request`), `actionlint`; container-first via `./dev run`.

---

## The central constraint (carry into every task)

**Signing keys must NEVER reach PR CI.** The bump PR builds **unsigned**
(`forge-bump-ci.yml`, no secrets, artefacts thrown away); the signed rebuild
happens only post-merge on `main` (`forge-release.yml`, SP4.4). The bump PR is
opened with a **GitHub App token, not `GITHUB_TOKEN`** — this is load-bearing, not
cosmetic: PRs authored by `GITHUB_TOKEN` do **not** trigger downstream workflows
(GitHub loop-prevention), so `forge-bump-ci` would silently never run and
shift-left would be a no-op. The App token both triggers CI and (via
`sign-commits`) produces API-signed commits that satisfy `required_signatures` on
`main`.

## Locked decisions (record verbatim in Task 0's commit)

1. **`latest_raw` is the only engine change.** `DetectedVersion` is frozen; add a
   required `latest_raw: str` field (no default — every field on this dataclass is
   required) carrying the verbatim upstream tag (`v1.11.1`), alongside the existing
   cleaned `latest` (`1.11.1`). The watch CLI emits both; the workflow bumps to
   `latest_raw` so download URLs keep working.
2. **Verbatim bump.** `mh bump --to "$TO"` writes `latest_raw` as-is (SP4.2
   decision). No v-strip/add in the workflow.
3. **Two workflows, not one.** Detection-side (`scan-updates.yml`) and
   validation-side (`forge-bump-ci.yml`) are separate concerns with different
   triggers, permissions, and secret exposure. `forge-bump-ci.yml` is **not**
   `forge-ci.yml` — a manifest-only change must build the package, not re-run the
   Python `make ci` gate (nothing changed there).
4. **Idempotent per item.** Fixed branch `bump/<item>`;
   `create-pull-request` updates the open PR instead of opening a duplicate on
   re-scan. One PR per item ⇒ disjoint paths ⇒ no cross-item conflict.
5. **Empty matrix is guarded.** The `bump` job runs only
   `if: needs.detect.outputs.items != '[]'` (profile: an empty matrix is a silent
   failure; guard-clause it).
6. **No untrusted data in `run:` scripts.** `latest_raw` originates from upstream
   `gh release list` tag names; bind every matrix/derived value to an `env:` and
   reference `"$VAR"` inside `run:` (never inline `${{ matrix.* }}` into a shell).
7. **Actions pinned by SHA** (profile + matches `forge-release.yml`). Verified
   latest at planning time:
   - `actions/checkout@df4cb1c069e1874edd31b4311f1884172cec0e10 # v6.0.3`
   - `actions/create-github-app-token@bcd2ba49218906704ab6c1aa796996da409d3eb1 # v3.2.0`
   - `peter-evans/create-pull-request@5f6978faf089d4d20b00c7766989d076bb2fc7f1 # v8.1.1`

## Prerequisites (user infra — not blocking the merge, flagged separately)

These are deployment steps the repo owner performs; the workflows merge safely
without them (the cron simply fails to open PRs until the secrets exist, blocking
nothing else):

- **GitHub App** (or fine-grained PAT) with `contents: write` + `pull-requests:
  write`, installed on the repo; store `BUMP_APP_ID` and `BUMP_APP_PRIVATE_KEY`
  repo secrets. Required because `GITHUB_TOKEN`-authored PRs don't trigger
  `forge-bump-ci` (see central constraint).
- **Branch protection:** add `forge-bump-ci` to the required status checks on
  `main` (so auto-merge waits for the unsigned build); keep **"Require branches to
  be up to date" OFF** (rebase would destroy SSH signatures — profile rule).

### Task 2: `forge-bump-ci.yml` — unsigned shift-left build

**Files:**
- Create: `.github/workflows/forge-bump-ci.yml`

- [ ] **Step 1: Write the workflow**

```yaml
name: forge-bump-ci

# Shift-left validation for bump PRs: build the changed item(s) UNSIGNED to prove
# the new upstream version packages cleanly. No secrets, no signing — artefacts are
# throwaway. The signed rebuild runs only post-merge on main (forge-release.yml).
# Triggers on any catalog/** change so manifest-only PRs build their package
# instead of (uselessly) re-running the Python gate in forge-ci.yml.

on:
  pull_request:
    paths:
      - "catalog/**"

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@df4cb1c069e1874edd31b4311f1884172cec0e10 # v6.0.3
        with:
          fetch-depth: 0
      - name: Identify changed items
        id: changed
        env:
          BASE_SHA: ${{ github.event.pull_request.base.sha }}
          HEAD_SHA: ${{ github.event.pull_request.head.sha }}
        run: |
          set -euo pipefail
          items=$(git diff --name-only "$BASE_SHA" "$HEAD_SHA" \
            | sed -n 's#^catalog/[^/]*/\([^/]*\)/manifest\.yaml$#\1#p' \
            | sort -u)
          {
            echo "items<<EOF"
            echo "$items"
            echo "EOF"
          } >> "$GITHUB_OUTPUT"
      - name: Build dev image
        if: steps.changed.outputs.items != ''
        run: ./dev build
      - name: Sync dependencies
        if: steps.changed.outputs.items != ''
        run: make sync
      - name: Build changed items (unsigned)
        if: steps.changed.outputs.items != ''
        env:
          ITEMS: ${{ steps.changed.outputs.items }}
        run: |
          set -euo pipefail
          while IFS= read -r item; do
            [ -n "$item" ] || continue
            echo "::group::build $item"
            ./dev run uv run mh build "$item" --out "./dist/$item"
            echo "::endgroup::"
          done <<< "$ITEMS"
```

### Task 3: `scan-updates.yml` — cron detect → signed bump PRs

**Files:**
- Create: `.github/workflows/scan-updates.yml`

- [ ] **Step 1: Write the workflow**

```yaml
name: scan-updates

# Every 6h: detect outdated exporters (mh watch) and open one signed, auto-merging
# bump PR per item. The PR is opened with a GitHub App token (NOT GITHUB_TOKEN) so
# its own forge-bump-ci checks actually trigger (shift-left) and its commits are
# API-signed (satisfy required_signatures on main). Idempotent: a fixed branch
# bump/<item> updates the open PR instead of opening duplicates.

on:
  schedule:
    - cron: "0 */6 * * *"
  workflow_dispatch:

permissions:
  contents: read

jobs:
  detect:
    runs-on: ubuntu-latest
    outputs:
      items: ${{ steps.scan.outputs.items }}
    steps:
      - uses: actions/checkout@df4cb1c069e1874edd31b4311f1884172cec0e10 # v6.0.3
      - name: Build dev image
        run: ./dev build
      - name: Sync dependencies
        run: make sync
      - name: Detect outdated items
        id: scan
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          set -euo pipefail
          ./dev run uv run mh watch --json > watch.json
          items=$(jq -c '[.[] | select(.outdated) | {item, kind, latest_raw}]' watch.json)
          echo "items=$items" >> "$GITHUB_OUTPUT"

  bump:
    needs: detect
    if: needs.detect.outputs.items != '[]'
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
    strategy:
      fail-fast: false
      matrix:
        target: ${{ fromJSON(needs.detect.outputs.items) }}
    steps:
      - uses: actions/checkout@df4cb1c069e1874edd31b4311f1884172cec0e10 # v6.0.3
      - name: Mint GitHub App token
        id: app-token
        uses: actions/create-github-app-token@bcd2ba49218906704ab6c1aa796996da409d3eb1 # v3.2.0
        with:
          app-id: ${{ secrets.BUMP_APP_ID }}
          private-key: ${{ secrets.BUMP_APP_PRIVATE_KEY }}
      - name: Build dev image
        run: ./dev build
      - name: Sync dependencies
        run: make sync
      - name: Bump manifest version
        env:
          ITEM: ${{ matrix.target.item }}
          TO: ${{ matrix.target.latest_raw }}
        run: ./dev run uv run mh bump "$ITEM" --to "$TO"
      - name: Create or update bump PR
        id: cpr
        uses: peter-evans/create-pull-request@5f6978faf089d4d20b00c7766989d076bb2fc7f1 # v8.1.1
        with:
          token: ${{ steps.app-token.outputs.token }}
          branch: bump/${{ matrix.target.item }}
          delete-branch: true
          sign-commits: true
          commit-message: "chore: bump ${{ matrix.target.item }} to ${{ matrix.target.latest_raw }}"
          title: "chore: bump ${{ matrix.target.item }} to ${{ matrix.target.latest_raw }}"
          body: |
            Automated upstream version bump for `${{ matrix.target.item }}`.

            - New version: `${{ matrix.target.latest_raw }}`
            - Source: github-release

            CI builds the package unsigned to validate the bump before merge.
      - name: Enable auto-merge
        if: steps.cpr.outputs.pull-request-number
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token }}
          PR: ${{ steps.cpr.outputs.pull-request-number }}
        run: gh pr merge --merge --auto "$PR"
```
