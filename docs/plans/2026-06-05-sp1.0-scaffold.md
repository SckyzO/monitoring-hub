# SP1.0 — Scaffold & Tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the greenfield `forge` package with an installable `mh` CLI, container-first tooling, and a green CI gate — the foundation every later SP1 increment builds on.

**Architecture:** New `src/forge/` package (src layout, hatchling), additive alongside the legacy `core/engine/` (legacy removal is deferred to the end-of-SP1 cutover, not this increment). All tooling (`uv`, `ruff`, `mypy --strict`, `pytest`) runs inside a dedicated non-root dev image driven by a thin `./dev` wrapper and a `Makefile`; CI calls the exact same targets.

**Tech Stack:** Python 3.12+, uv, hatchling (PEP 517), Click, ruff, mypy `--strict`, pytest (+xdist, +cov); security: bandit (SAST) + pip-audit (dep CVE) + gitleaks (secrets) + trivy (fs/image CVE); pre-commit suite (hadolint, actionlint, shellcheck, shfmt, yamllint, markdownlint, conventional-commits); Docker dev image, GitHub Actions.

**Quality/security bar (mirrors and exceeds the legacy Makefile + pre-commit + security.yml):**
- The legacy stack ran ruff + pytest via `make ci`, a rich pre-commit suite (gitleaks/hadolint/actionlint/shellcheck/shfmt/yamllint/markdownlint/conventional-commits), and a `security.yml` (bandit/pip-audit/trivy). mypy was **disabled** (legacy code did not pass `--strict`).
- This greenfield scaffold keeps that whole surface **and turns mypy `--strict` ON** (typed from line one). `make ci` now also runs `bandit` + `pip-audit`; a greenfield `security.yml` runs bandit/pip-audit/trivy/gitleaks-history.

**Scope of this increment (SP1.0 only):**
- In: `pyproject.toml`, `src/forge/` skeleton, `mh` console-script (`--version` + empty group), ruff/mypy/pytest config, **bandit + pip-audit security gate**, **`.pre-commit-config.yaml`** (multi-language lint + secrets + conventional commits), dev image + `./dev` wrapper + `Makefile`, **CI workflow + greenfield `security.yml`**, one passing test.
- Out (later SP1 increments): domain models (SP1.1), sources/overlay (SP1.2), producers (SP1.3/1.4), catalog builder + full CLI commands (SP1.5), legacy `core/engine/` removal (handled by the greenfield cutover preceding this scaffold).

## Task 2: Dev image + `./dev` wrapper (container-first, non-root)

**Files:**
- Create: `Dockerfile.dev`
- Create: `dev`
- Create: `.dockerignore`

- [ ] **Step 1: Create `Dockerfile.dev`**

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.12-slim

# Match the host user so files created in the mounted volume stay owned by the host user.
ARG USER_UID=1000
ARG USER_GID=1000

RUN groupadd --gid "${USER_GID}" dev \
    && useradd --uid "${USER_UID}" --gid "${USER_GID}" --create-home --shell /bin/bash dev

# uv: the package manager (pinned by digest is preferable in CI; see version note).
COPY --from=ghcr.io/astral-sh/uv:latest /uv /usr/local/bin/uv

WORKDIR /workspace
ENV UV_LINK_MODE=copy \
    UV_PROJECT_ENVIRONMENT=/home/dev/.venv \
    PATH="/home/dev/.venv/bin:${PATH}"

USER dev
```

- [ ] **Step 2: Create the `dev` wrapper**

```bash
#!/usr/bin/env bash
set -euo pipefail

IMAGE="forge-dev"
UID_GID="$(id -u):$(id -g)"

case "${1:-}" in
  build)
    docker build \
      --build-arg "USER_UID=$(id -u)" \
      --build-arg "USER_GID=$(id -g)" \
      -f Dockerfile.dev -t "${IMAGE}" .
    ;;
  shell)
    docker run --rm -it -u "${UID_GID}" \
      -v "$(pwd):/workspace" "${IMAGE}" bash
    ;;
  run)
    shift
    docker run --rm -u "${UID_GID}" \
      -v "$(pwd):/workspace" "${IMAGE}" "$@"
    ;;
  *)
    echo "usage: ./dev {build|shell|run <cmd...>}" >&2
    exit 2
    ;;
esac
```
