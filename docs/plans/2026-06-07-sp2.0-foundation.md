# SP2.0 — Distribution Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lay the foundation for SP2 distribution — extend the dev image with the repo/OCI tooling, add the typed errors and the `Publisher` contract, and scaffold the `forge/repo/` and `forge/publish/` packages — so SP2.1+ can build on a green base.

**Architecture:** Pure scaffolding increment, no behavioural feature. Two new layers (`repo/` generates files, `publish/` isolates network I/O) are created as empty packages plus the `Publisher` Protocol contract (the same "contract only" pattern as `kinds/base.py` in SP1.1). The dev image gains `createrepo_c`, `apt-utils`, `buildah`, `skopeo`, `gnupg`, `qemu-user-static` from Debian packages (no manual tarballs). `Artifact.url` needs **no** schema change — its population logic lands in SP2.1/SP2.3 where it is actually used (no dead code).

**Tech Stack:** Python 3.12, Pydantic v2, Click, pytest, container-first (`./dev run`, `make ci` on host), Docker (`Dockerfile.dev`).

**Reference spec:** `docs/specs/2026-06-07-sp2-distribution.md` (§4 architecture, §5.5 Publisher, §10 decomposition).

## Task 1: Extend the dev image

**Files:**
- Modify: `Dockerfile.dev`

The new tools are all Debian packages (the base is `python:3.12-slim`), so a single `apt-get install` layer suffices — no manual tarball like nfpm. Add them in their own layer, after the existing base-deps layer, so the nfpm layer cache is preserved.

- [ ] **Step 1: Add the distribution tooling layer to `Dockerfile.dev`**

Insert this block immediately **after** the existing base-deps `RUN apt-get ... git ca-certificates curl libatomic1 ...` block and **before** the `COPY --from=ghcr.io/astral-sh/uv` line:

```dockerfile
# SP2 distribution tooling, all from Debian packages:
#   createrepo-c   -> yum/RPM repo metadata (repodata/, repomd.xml)
#   apt-utils      -> apt-ftparchive, the stateless flat APT repo generator
#   buildah        -> daemonless, rootless OCI image build (no docker socket)
#   skopeo         -> copy/push OCI images + multi-arch manifests
#   gnupg          -> sign repo metadata (repomd.xml.asc, InRelease, Release.gpg)
#   qemu-user-static + binfmt-support -> cross-arch (arm64) emulation for buildah
# hadolint ignore=DL3008
RUN apt-get update \
    && apt-get install -y --no-install-recommends \
    createrepo-c apt-utils buildah skopeo gnupg qemu-user-static binfmt-support \
    && rm -rf /var/lib/apt/lists/*
```

- [ ] **Step 2: Rebuild the dev image**

Run: `./dev build`
Expected: image `forge-dev` builds without error (it will be noticeably larger — buildah/skopeo/qemu pull a fair amount; acceptable for a dev image).


Expected: each command prints a version line, exit 0. (Note the binary is `createrepo_c` with an underscore even though the Debian package is `createrepo-c`.)

## Task 2: Typed errors for the new layers

**Files:**
- Modify: `src/forge/domain/errors.py`
- Test: `tests/domain/test_errors.py`

Two new errors, mirroring the SP1.1 precedent of declaring the hierarchy as a contract: `DistributionError` (repo-tree generation failed) and `PublishError` (pushing to a remote failed). Both inherit `ForgeError`, so the CLI's existing top-level `ForgeError` handler catches them.

- [ ] **Step 1: Write the failing test**

Append to `tests/domain/test_errors.py` (create the file with this content if it does not exist):

```python
"""The typed error hierarchy stays flat and rooted at ForgeError."""

from __future__ import annotations

from forge.domain.errors import DistributionError, ForgeError, PublishError


def test_distribution_error_is_a_forge_error() -> None:
    assert issubclass(DistributionError, ForgeError)


def test_publish_error_is_a_forge_error() -> None:
    assert issubclass(PublishError, ForgeError)
```

- [ ] **Step 2: Run test to verify it fails**

Run: `./dev run uv run pytest tests/domain/test_errors.py -v`
Expected: FAIL with `ImportError: cannot import name 'DistributionError'`.

- [ ] **Step 3: Add the two errors**

Append to `src/forge/domain/errors.py`:

```python
class DistributionError(ForgeError):
    """Generating a repository tree (rpm/apt metadata, signing) failed."""


class PublishError(ForgeError):
    """Publishing artifacts to a remote (GitHub Releases, OCI registry) failed."""
```

- [ ] **Step 4: Run test to verify it passes**

Run: `./dev run uv run pytest tests/domain/test_errors.py -v`
Expected: PASS (2 passed).

## Task 4: Scaffold `forge/publish/` + the `Publisher` contract

**Files:**
- Create: `src/forge/publish/__init__.py`
- Create: `src/forge/publish/base.py`
- Create: `tests/publish/__init__.py`
- Create: `tests/publish/test_base.py`

The `Publisher` Protocol is the publish contract (host-agnostic), exactly like `kinds/base.py`'s `Producer` Protocol in SP1.1. `@runtime_checkable` lets a test assert conformance via `isinstance`, which also proves the Protocol is not dead — it has a verified consumer shape.

- [ ] **Step 1: Create the package marker**

Create `src/forge/publish/__init__.py`:

```python
"""Publishing layer (spec §4, §5.5-5.7).

The single boundary for network I/O: a ``Publisher`` pushes a staging tree to a
remote. Concrete adapters (GitHub Releases, OCI/GHCR; later S3-compatible R2 /
Garage / MinIO) land in SP2.4-SP2.5. Swapping the blob host is one new adapter,
no change elsewhere.
"""
```

- [ ] **Step 2: Write the failing test for the contract**

Create `tests/publish/__init__.py` (empty file), then create `tests/publish/test_base.py`:

```python
"""The Publisher protocol is the host-agnostic publish contract."""

from __future__ import annotations

from pathlib import Path

from forge.publish.base import Publisher


class _FakePublisher:
    def __init__(self) -> None:
        self.published: list[Path] = []

    def publish(self, staging: Path) -> None:
        self.published.append(staging)


def test_conforming_object_is_a_publisher() -> None:
    assert isinstance(_FakePublisher(), Publisher)


def test_non_conforming_object_is_not_a_publisher() -> None:
    assert not isinstance(object(), Publisher)


def test_publish_receives_the_staging_path() -> None:
    pub = _FakePublisher()
    pub.publish(Path("/tmp/release"))
    assert pub.published == [Path("/tmp/release")]
```

- [ ] **Step 3: Run test to verify it fails**

Run: `./dev run uv run pytest tests/publish/test_base.py -v`
Expected: FAIL with `ModuleNotFoundError: No module named 'forge.publish.base'`.

- [ ] **Step 4: Create the Protocol**

Create `src/forge/publish/base.py`:

```python
"""Publisher protocol: the host-agnostic publish contract (spec §5.5).

A ``Publisher`` takes a local staging tree and pushes it to one remote. The
implementation owns all network I/O and the auth it needs; callers stay
host-agnostic so the blob host can change by swapping the adapter.
"""

from __future__ import annotations

from pathlib import Path
from typing import Protocol, runtime_checkable


@runtime_checkable
class Publisher(Protocol):
    def publish(self, staging: Path) -> None: ...
```

Run: `./dev run uv run pytest tests/publish/test_base.py -v`
Expected: PASS (3 passed).
